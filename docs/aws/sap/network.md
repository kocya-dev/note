## ネットワーク

- AWS Transit Gateway
  - VPC 間の接続を一元化
  - VPC ピアリングの代替
  - VPN 接続や Direct Connect の統合
- AWS Direct Connect
  - オンプレミスと AWS 間の専用線接続
  - 高速で安定したネットワーク接続
  - 帯域幅の選択肢が豊富
- AWS Direct Connect Gateway
  - 複数の VPC への接続を簡素化
  - Transit Gateway と統合可能
- AWS VPN
  - オンプレミスと AWS 間の VPN 接続
  - セキュアな通信を提供
  - AWS Transit Gateway と統合可能
- AWS NAT Gateway
  - プライベートサブネットからインターネットへのアクセスを提供
  - 高可用性とスケーラビリティを持つ
  - セキュリティグループは適用不可（NAT Gateway 自体に関連付け不可）。ネットワーク ACL とルートテーブルで制御
- Site to Site VPN
  - オンプレミスのネットワークと AWS VPC 間の VPN 接続
  - 複数の VPN 接続をサポート
  - 高可用性と冗長性を提供
- Private Link
  - VPC 内のサービスへのプライベートアクセスを提供
  - サービスプロバイダーとサービスコンシューマー間のセキュアな接続
  - VPC エンドポイントを使用して、インターネットを経由せずにサービスにアクセス
- トランジット仮想インターフェース
  - Direct Connect 接続を複数の VPC やオンプレミスネットワークに分割
  - トラフィックの分離と管理を簡素化
  - パブリック仮想インターフェース、プライベート仮想インターフェース、トランジット仮想インターフェースの 3 種類がある
- VIF (Virtual Interface)
  - Direct Connect 接続上での論理的なネットワークインターフェース
  - パブリック仮想インターフェース、プライベート仮想インターフェース、トランジット仮想インターフェースの 3 種類がある

```
リージョン間 オンプレ-AWSのルーティング例

オンプレミス1
  |
  |--- Direct Connect --- Direct Connect Gateway --- Transit Gateway --- VPC1
                                                            |       |
                                                            |       |--- VPC2
オンプレミス2                                                |(peering)
  |                                                         |
  |--- Direct Connect --- Direct Connect Gateway --- Transit Gateway --- VPC1
                                                                    |
                                                                    |--- VPC2
```

Transit Gateway / VPC Peering / Site to Site VPN では VPC を跨いだ状態でも CIDR の重複はできない。

- Elastic Network Interface

  - VPC 内の仮想ネットワークインターフェース
  - EC2 インスタンスにアタッチ可能
  - 複数の IP アドレスを持つことができる

- API Gateway

  - RESTful API の作成と管理をサポート
  - Lambda 関数や他の AWS サービスとの統合
  - スケーラブルな API エンドポイントを提供
  - Regional API と Edge-Optimized API の選択肢

- AWS AppSync

  - GraphQL API の作成と管理をサポート
  - データソースとして DynamoDB、Lambda、RDS などを統合
  - リアルタイムデータの同期を提供

- AWS Global Accelerator

  - エッジロケーションから最適経路でのトラフィック転送を行う。
  - any cast IP による IP アドレス固定化
  - ヘルスチェック機能あり
    - フェイルオーバー数秒以内に完結
      (Route53 では数十秒～数分かかる)

- VPC

  - VPC Endpoint
    - インターフェースエンドポイント
      - VPC 内のサービスへのプライベートアクセスを提供
      - AWS PrivateLink を使用して、インターネットを経由せずにサービスにアクセス
    - ゲートウェイエンドポイント
      - S3 や DynamoDB などの AWS サービスへのプライベートアクセスを提供
      - インターネットを経由せずにサービスにアクセス
  - enableDnsSupport 属性（DNS サポート）を有効にすることで、VPC が DNS ホスト名を IP アドレスに解決できるようになる。
  - enableDnsHostnames 属性（DNS ホスト名）を有効にすることで、パブリック IP アドレスを持つインスタンスがパブリックホスト名を受け取ることができる。

- Route 53

  - DNS サービス
  - ドメイン名の登録、DNS レコードの管理
  - ヘルスチェック機能を提供
  - Route 53 Resolver によるオンプレミス DNS と AWS の統合
  - レイテンシベースのルーティング、地理的ルーティング、加重ルーティングなどの高度なルーティング機能を提供

    - 地理的ルーティング
      - ユーザーの地理的な位置に基づいて、特定のエンドポイントにトラフィックをルーティング
    - レイテンシベースのルーティング
      - ユーザーから見て応答が速い（遅延が少ない）サーバーに接続する
    - 加重ルーティング
      - 複数のエンドポイントに重みを付けてトラフィックを分散

  - Amazon Route 53 Resolver
    - オンプレミスの DNS と AWS の VPC 内の DNS を統合
    - フルマネージドな DNS 解決サービス
    - VPC 内のリソースがオンプレミスの DNS 名を解決できるようにする

### AWS Outposts

- 顧客オンプレミスに AWS インフラを拡張するフルマネージドハイブリッドクラウドサービス
- AWS Region と同じ API、ツール、プログラミングインターフェースを提供
- 低レイテンシやローカルデータ処理が必要なワークロードに対応

#### 形態・構成要素

- **Outposts Rack**: 42U ラック形式（サーバー、スイッチ、電源等含む）
- **Outposts Server**: 1U/2U サーバー形式（限定スペース・小規模容量向け）
- **ACE Rack**: 4 ラック以上のマルチラック展開時のネットワーク集約点

#### 主要コンポーネント

- **Outpost Site**: 顧客管理の物理施設（電力・ネットワーク・設備要件を満たす必要）
- **Service Link**: Outpost と AWS Region を結ぶネットワーク経路
- **Local Gateway**: Outposts Rack とオンプレミスネットワーク間の論理ルーター
- **Local Network Interface**: Outposts Server とオンプレミスネットワーク間のインターフェース

#### 対応サービス（Rack/Server）

- **コンピュート**: EC2 インスタンス（両方）、ECS クラスター（両方）、EKS ノード（Rack のみ）
- **ストレージ**: EBS ボリューム（Rack のみ）、S3 バケット（Rack のみ）
- **データベース**: RDS（Rack のみ）、ElastiCache（Rack のみ）、EMR（Rack のみ）
- **ネットワーク**: VPC サブネット（両方）、ALB（Rack のみ）、App Mesh（両方）

#### 主要用途

- データ所在地要件がある規制対応ワークロード
- 極低レイテンシが必要なリアルタイム処理
- オンプレミスシステムとの密な連携が必要なアプリケーション
- 段階的なクラウド移行における橋渡し

### AWS Snowball Edge Compute Optimized デバイス

AWS Snowball Edge Compute Optimized は、エッジコンピューティングに特化した堅牢な物理デバイスです。

#### 主要仕様

- **CPU**: AMD EPYC Gen2、64 コア、2 GHz
- **vCPU**: 104 vCPU
- **メモリ**: 416GB（使用可能領域）、512GB（総容量）
- **ストレージ**: 28TB NVMe SSD（コンピュートインスタンス専用）

#### ネットワーク機能

- 2x 10 Gbit RJ45 ポート（1 つ使用可能）
- 1x 25 Gbit SFP28
- 1x 100 Gbit QSFP28

#### 物理特性

- **重量**: 22.54kg
- **寸法**: 39.4cm(H) × 26.5cm(W) × 71.8cm(L)
- **消費電力**: 304W（平均使用時）、最大 1200W
- **動作温度**: 0-45°C

#### 用途

- Amazon EC2 互換インスタンスの実行
- オフライン環境での AWS サービス提供
- エッジコンピューティングワークロード
- ハイブリッドクラウド環境での計算処理

このデバイスにより、AWS クラウドの計算能力を物理的にオンプレミス環境に展開できます。

## CDN

- AWS CloudFront
  - コンテンツ配信ネットワーク (CDN) サービス
  - グローバルなエッジロケーションを利用して低遅延でコンテンツを配信
  - 動的コンテンツや静的コンテンツのキャッシュをサポート
  - AWS WAF と統合可能
  - フィールドレベル暗号化
    - データの特定のフィールドがオリジンに転送される前に暗号化される。
  - オリジングループ
    - 複数のオリジンをグループ化し、フェイルオーバーや負荷分散を実現
      - フェイルオーバー動作させるステータスコードは設定可能
    - プライマリオリジンが利用できない場合にセカンダリオリジンに自動的に切り替え
  - Lambda@edge
    - CloudFront エッジロケーションでの Lambda 関数実行
    - レイテンシの低減とグローバルなアプリケーションの最適化
    - レスポンスの加工(特定ヘッダの削除など)では API Gateway で処理するよりも遅延を減らすことができる。
      また、柔軟性やスケーラビリティ観点でも優れている

## 負荷分散

- AWS Application Load Balancer (ALB)
  - HTTP/HTTPS トラフィックの負荷分散
  - レイヤー 7 のルーティング機能を提供
  - WebSocket や HTTP/2 のサポート
  - スティッキーセッション
    - 特定のクライアントからのリクエストを同じターゲットにルーティング
    - セッション情報を保持するためのクッキーを使用
- AWS Network Load Balancer (NLB)

  - TCP/UDP トラフィックの負荷分散
  - レイヤー 4 の負荷分散を提供
  - 高いスループットと低レイテンシを実現
  - ルーティング
    - フローハッシュに基づいて分散（同一フローは同一ターゲットへ）。NLB では ALB のようなラウンドロビン/最小未処理リクエストのアルゴリズム切替は不可

- AWS Gateway Load Balancer (GWLB)
  - ネットワークトラフィックの負荷分散
  - セキュリティアプライアンスやネットワーク機器との統合
  - レイヤー 3 の負荷分散を提供
  - 全インバウンド/アウトバウンド通信をリダイレクトして、セキュリティツールに送信可能
- Elastic Load Balancing (ELB)
  - ALB、NLB、GWLB の総称
  - 高可用性とスケーラビリティを提供
  - 自動的なヘルスチェックとフェイルオーバー機能を持つ
